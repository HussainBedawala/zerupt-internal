# ZATCA Electronic Invoice XML Implementation Standard
## Exhaustive Field Reference — v1.2 (2023-05-19)

Source: *Electronic Invoice XML Implementation Standard to the E-Invoicing resolution dated 2023-05-19*, Version 1.2  
UBL version: 2.1 · Main namespace: `urn:oasis:names:specification:ubl:schema:xsd:Invoice-2`

---

## 1. Invoice Type Codes & Subtypes

### 1.1 `cbc:InvoiceTypeCode` — the numeric value

| UN/CEFACT code | Description |
|---|---|
| `388` | Standard Tax Invoice |
| `383` | Debit Note |
| `381` | Credit Note |
| `386` | Prepayment Invoice |

All document types use the UBL **Invoice** message. The UBL `CreditNoteTypeCode` is **not** used; credit notes also use `Invoice` with type code 381.

### 1.2 `@name` attribute — the 7-digit transaction code (KSA-2)

Structure: **NNPNESB**

| Position | Meaning | Values |
|---|---|---|
| 1–2 (NN) | Invoice subtype | `01` = Standard Tax Invoice; `02` = Simplified Tax Invoice |
| 3 (P) | Third-party invoice | `0` false / `1` true |
| 4 (N) | Nominal supply | `0` false / `1` true |
| 5 (E) | Export invoice | `0` false / `1` true |
| 6 (S) | Summary invoice | `0` false / `1` true |
| 7 (B) | Self-billed invoice | `0` false / `1` true |

**Examples (exhaustive, from the spec):**

```xml
<!-- Standard Tax Invoice -->
<cbc:InvoiceTypeCode name="0100000">388</cbc:InvoiceTypeCode>

<!-- Simplified Tax Invoice -->
<cbc:InvoiceTypeCode name="0200000">388</cbc:InvoiceTypeCode>

<!-- Standard Tax Invoice Debit Note -->
<cbc:InvoiceTypeCode name="0100000">383</cbc:InvoiceTypeCode>

<!-- Simplified Tax Invoice Debit Note -->
<cbc:InvoiceTypeCode name="0200000">383</cbc:InvoiceTypeCode>

<!-- Standard Tax Invoice Credit Note -->
<cbc:InvoiceTypeCode name="0100000">381</cbc:InvoiceTypeCode>

<!-- Simplified Tax Invoice Credit Note -->
<cbc:InvoiceTypeCode name="0200000">381</cbc:InvoiceTypeCode>

<!-- Prepayment Standard Tax Invoice -->
<cbc:InvoiceTypeCode name="0100000">386</cbc:InvoiceTypeCode>

<!-- Prepayment Simplified Tax Invoice -->
<cbc:InvoiceTypeCode name="0200000">386</cbc:InvoiceTypeCode>
```

**Constraints on flags:**
- BR-KSA-07: Self-billing (position 7 = 1) is NOT allowed for export invoices (position 5 = 1).
- BR-KSA-31: For simplified invoices (positions 1–2 = `02`), only third-party (pos 3), nominal supply (pos 4), and summary (pos 6) flags are accepted.

### 2.2 `cac:AdditionalDocumentReference` — three mandatory blocks

**ICV (Invoice Counter Value) — KSA-16**

```xml
<cac:AdditionalDocumentReference>
  <cbc:ID>ICV</cbc:ID>
  <cbc:UUID><!-- monotonically increasing integer --></cbc:UUID>
</cac:AdditionalDocumentReference>
```
- `cbc:ID` = literal `"ICV"`.
- `cbc:UUID` = the counter value (digits only). BR-KSA-33, BR-KSA-34.

**PIH (Previous Invoice Hash) — KSA-13**

```xml
<cac:AdditionalDocumentReference>
  <cbc:ID>PIH</cbc:ID>
  <cac:Attachment>
    <cbc:EmbeddedDocumentBinaryObject mimeCode="text/plain">
      <!-- Base64-encoded SHA-256 hash of the previous invoice -->
    </cbc:EmbeddedDocumentBinaryObject>
  </cac:Attachment>
</cac:AdditionalDocumentReference>
```
- `cbc:ID` = literal `"PIH"`.
- Must be base64-encoded SHA-256. BR-KSA-26, BR-KSA-61 (mandatory in every invoice).
- **Hash computation:** (1) Remove `<ext:UBLExtensions/>` block; (2) Remove `<cac:AdditionalDocumentReference>` where `cbc:ID` = `"QR"`; (3) Remove `<cac:Signature/>` block; (4) Canonicalize using C14N11; (5) SHA-256 hash to binary; (6) Base64-encode.
- **First invoice:** use `NWZlY2ViNjZmZmM4NmYzOGQ5NTI3ODZjNmQ2OTZjNzljMmRiYzIzOWRkNGU5MWI0NjcyOWQ3M2EyN2ZiNTdlOQ==` (= base64(SHA256("0"))).

**QR Code — KSA-14**

```xml
<cac:AdditionalDocumentReference>
  <cbc:ID>QR</cbc:ID>
  <cac:Attachment>
    <cbc:EmbeddedDocumentBinaryObject mimeCode="image/png">
      <!-- Base64Binary QR code -->
    </cbc:EmbeddedDocumentBinaryObject>
  </cac:Attachment>
</cac:AdditionalDocumentReference>
```
- `cbc:ID` = literal `"QR"`.
- Must be base64Binary. BR-KSA-27. Full specification in Security Features Implementation Standards.

### 2.3 Signature Block — KSA-15

```xml
<cac:Signature>
  <cbc:ID>urn:oasis:names:specification:ubl:signature:Invoice</cbc:ID>
  <cbc:SignatureMethod>urn:oasis:names:specification:ubl:dsig:enveloped:xades</cbc:SignatureMethod>
</cac:Signature>
```
- Signature information ID: `urn:oasis:names:specification:ubl:signature:1` — BR-KSA-28.
- Referenced signature ID and signature ID: `urn:oasis:names:specification:ubl:signature:Invoice` — BR-KSA-29.
- Signature method: `urn:oasis:names:specification:ubl:dsig:enveloped:xades` — BR-KSA-30.
- **Simplified invoices:** cryptographic stamp is **mandatory** (BR-KSA-60).
- **Standard tax invoices:** cryptographic stamp is optional per the spec (present if exists).

### 2.4 Billing Reference (Credit/Debit Notes)

```xml
<cac:BillingReference>
  <cac:InvoiceDocumentReference>
    <cbc:ID><!-- original invoice number --></cbc:ID>
    <cbc:IssueDate><!-- YYYY-MM-DD --></cbc:IssueDate>
  </cac:InvoiceDocumentReference>
</cac:BillingReference>
```
- Mandatory for debit notes (383) and credit notes (381). BR-KSA-56.
- BR-55: `cbc:ID` (BT-25) is mandatory in each `cac:BillingReference`.

### 2.9 Document-Level Allowances & Charges — `cac:AllowanceCharge`

```xml
<cac:AllowanceCharge>
  <cbc:ChargeIndicator>false</cbc:ChargeIndicator>  <!-- false = allowance, true = charge -->
  <cbc:AllowanceChargeReasonCode>95</cbc:AllowanceChargeReasonCode>  <!-- UNTDID 5189 (allowance) or 7161 (charge) -->
  <cbc:AllowanceChargeReason>Discount</cbc:AllowanceChargeReason>
  <cbc:MultiplierFactorNumeric>10</cbc:MultiplierFactorNumeric>  <!-- percentage, 0.00–100.00 -->
  <cbc:Amount currencyID="SAR">200</cbc:Amount>
  <cbc:BaseAmount currencyID="SAR">2000</cbc:BaseAmount>
  <cac:TaxCategory>
    <cbc:ID>S</cbc:ID>
    <cbc:Percent>15</cbc:Percent>
    <cac:TaxScheme><cbc:ID>VAT</cbc:ID></cac:TaxScheme>
  </cac:TaxCategory>
</cac:AllowanceCharge>
```

- BR-31: Amount (BT-92) mandatory for each document-level allowance.
- BR-32: VAT category code (BT-95) mandatory for each document-level allowance.
- BR-36: Amount (BT-99) mandatory for each document-level charge.
- BR-37: VAT category code (BT-102) mandatory for each document-level charge.
- BR-KSA-19: Charge reason code (BT-105) mandatory for every document-level charge.
- BR-KSA-21: Charge reason text (BT-104) mandatory for every document-level charge.
- Allowance reason code: UNTDID 5189; charge reason code: UNTDID 7161.
- If base amount provided, percentage must also be present and vice versa (BR-KSA-EN16931-04, -05).
- Amount = Base amount × (Percentage ÷ 100).

### 2.10 Tax Totals — `cac:TaxTotal`

Two `cac:TaxTotal` blocks when `cbc:TaxCurrencyCode` differs from `cbc:DocumentCurrencyCode`:
- **Block 1 (with subtotals):** amounts in invoice currency, contains `cac:TaxSubtotal` breakdown.
- **Block 2 (without subtotals):** a single `cbc:TaxAmount` in SAR (the VAT accounting currency amount, BT-111).

BR-KSA-EN16931-08: Only one TaxTotal with subtotals allowed.  
BR-KSA-EN16931-09: Only one TaxTotal without subtotals allowed (when tax currency code present).

```xml
<!-- Block 1: with subtotals (invoice currency) -->
<cac:TaxTotal>
  <cbc:TaxAmount currencyID="SAR">885</cbc:TaxAmount>
  <cac:TaxSubtotal>
    <cbc:TaxableAmount currencyID="SAR">5900</cbc:TaxableAmount>
    <cbc:TaxAmount currencyID="SAR">885</cbc:TaxAmount>
    <cac:TaxCategory>
      <cbc:ID>S</cbc:ID>
      <cbc:Percent>15</cbc:Percent>
      <cac:TaxScheme><cbc:ID>VAT</cbc:ID></cac:TaxScheme>
    </cac:TaxCategory>
  </cac:TaxSubtotal>
  <!-- one TaxSubtotal per distinct VAT category code + rate combination -->
</cac:TaxTotal>

<!-- Block 2: without subtotals (SAR) — only when TaxCurrencyCode != DocumentCurrencyCode -->
<cac:TaxTotal>
  <cbc:TaxAmount currencyID="SAR"><!-- BT-111, VAT in SAR --></cbc:TaxAmount>
</cac:TaxTotal>
```

**TaxSubtotal mandatory fields:**
- `cbc:TaxableAmount` (BT-116) — BR-45, max 2 decimals (BR-DEC-19).
- `cbc:TaxAmount` (BT-117) — BR-46, max 2 decimals (BR-DEC-20).
- `cac:TaxCategory/cbc:ID` (BT-118) — BR-47.
- `cac:TaxCategory/cbc:Percent` (BT-119) — BR-48 (except for "Not subject to VAT" O).
- For E, Z, O: `cbc:TaxExemptionReasonCode` (BT-121) — mandatory (BR-KSA-23, BR-KSA-24, BR-KSA-69).
- For E, Z, O: `cbc:TaxExemptionReason` (BT-120) — mandatory text from list at 11.2.4 (BR-KSA-83, BR-KSA-CL-05).

### 2.12 Invoice Lines — `cac:InvoiceLine`

```xml
<cac:InvoiceLine>
  <cbc:ID>1</cbc:ID>                           <!-- BT-126, mandatory. BR-21. -->
  <cbc:Note>...</cbc:Note>                     <!-- Optional note -->
  <cbc:InvoicedQuantity unitCode="PCE">10</cbc:InvoicedQuantity>  <!-- BT-129, mandatory. BR-22. unitCode from UN/ECE Rec20. -->
  <cbc:LineExtensionAmount currencyID="SAR">2000.00</cbc:LineExtensionAmount>  <!-- BT-131, mandatory. BR-24. max 2 dec. -->

  <!-- Optional line-level allowance/charge -->
  <cac:AllowanceCharge>
    <cbc:ChargeIndicator>false</cbc:ChargeIndicator>
    <cbc:AllowanceChargeReasonCode>95</cbc:AllowanceChargeReasonCode>
    <cbc:AllowanceChargeReason>Discount</cbc:AllowanceChargeReason>
    <cbc:Amount currencyID="SAR">100.00</cbc:Amount>   <!-- BT-136. max 2 dec. -->
    <cbc:BaseAmount currencyID="SAR">1000.00</cbc:BaseAmount>  <!-- BT-137. max 2 dec. -->
  </cac:AllowanceCharge>

  <!-- Line-level TaxTotal: mandatory for standard (01) invoices -->
  <cac:TaxTotal>
    <cbc:TaxAmount currencyID="SAR">300.00</cbc:TaxAmount>       <!-- KSA-11: line VAT amount. Mandatory for 01. BR-KSA-52. -->
    <cbc:RoundingAmount currencyID="SAR">2300.00</cbc:RoundingAmount>  <!-- KSA-12: line amount with VAT. Mandatory for 01. BR-KSA-53. -->
  </cac:TaxTotal>

  <cac:Item>
    <cbc:Name>Product Name</cbc:Name>   <!-- BT-153, mandatory. BR-25. -->
    <cac:SellersItemIdentification><cbc:ID>SKU001</cbc:ID></cac:SellersItemIdentification>
    <cac:BuyersItemIdentification><cbc:ID>BID001</cbc:ID></cac:BuyersItemIdentification>
    <cac:ClassifiedTaxCategory>
      <cbc:ID>S</cbc:ID>          <!-- BT-151, mandatory. BR-CO-04. -->
      <cbc:Percent>15.00</cbc:Percent>  <!-- BT-152. -->
      <cac:TaxScheme><cbc:ID>VAT</cbc:ID></cac:TaxScheme>
    </cac:ClassifiedTaxCategory>
  </cac:Item>

  <cac:Price>
    <cbc:PriceAmount currencyID="SAR">200</cbc:PriceAmount>  <!-- BT-146, mandatory. BR-26. -->
    <cbc:BaseQuantity unitCode="PCE">1</cbc:BaseQuantity>    <!-- BT-149. Must be positive. BR-KSA-EN16931-12. -->
    <cac:AllowanceCharge>  <!-- Price-level discount (BT-147/148) -->
      <cbc:ChargeIndicator>false</cbc:ChargeIndicator>
      <cbc:Amount currencyID="SAR">50</cbc:Amount>          <!-- BT-147 -->
      <cbc:BaseAmount currencyID="SAR">250</cbc:BaseAmount> <!-- BT-148 -->
    </cac:AllowanceCharge>
  </cac:Price>
</cac:InvoiceLine>
```

**Line-level calculations:**
- Item net price (BT-146) = Gross price (BT-148) − Item price discount (BT-147), when gross price exists.
- Invoice line net amount (BT-131) = ((BT-146 ÷ BT-149) × BT-129) − line allowances + line charges.
- KSA-11 (line VAT amount) = BT-131 × (BT-152 ÷ 100). BR-KSA-50.
- KSA-12 (line amount with VAT) = BT-131 + KSA-11. BR-KSA-51.

**Line-level charge rules:** BR-KSA-20 (charge reason code mandatory), BR-KSA-22 (charge reason text mandatory).

## 7. Currency Rules

### 7.1 DocumentCurrencyCode (BT-5)
- ISO 4217 alpha-3. Can be any currency (e.g., USD, EUR, SAR).
- All monetary amounts in the invoice use this currency, with `@currencyID` attribute = this value.
- BR-KSA-CL-02: ALL currencyID attributes must match DocumentCurrencyCode, except for BT-111.

### 7.2 TaxCurrencyCode (BT-6)
- Must exist (BR-KSA-68) and must be `"SAR"` (BR-KSA-EN16931-02).
- Even if DocumentCurrencyCode is already SAR, TaxCurrencyCode must still be present.

### 7.3 VAT Amount in SAR (BT-111)
- When DocumentCurrencyCode ≠ SAR (or when TaxCurrencyCode is provided per BR-53):
  - A second `cac:TaxTotal` block must be provided with `cbc:TaxAmount @currencyID="SAR"` = BT-111.
  - This block has no `cac:TaxSubtotal` children.
  - Max 2 decimals (BR-DEC-15).
- The primary TaxTotal (with subtotals) uses DocumentCurrencyCode.

### 7.4 The Two-TaxTotal Pattern (when SAR ≠ DocumentCurrencyCode)

```xml
<!-- Primary TaxTotal: invoice currency, with VAT breakdown -->
<cac:TaxTotal>
  <cbc:TaxAmount currencyID="USD">100.00</cbc:TaxAmount>   <!-- BT-110 in USD -->
  <cac:TaxSubtotal>...</cac:TaxSubtotal>
</cac:TaxTotal>

<!-- Secondary TaxTotal: SAR only, no subtotals -->
<cac:TaxTotal>
  <cbc:TaxAmount currencyID="SAR">375.00</cbc:TaxAmount>   <!-- BT-111 in SAR -->
</cac:TaxTotal>
```

## 8. VAT Calculation Rules

### 8.1 VAT Breakdown (one per distinct category code + rate combination)

```
VAT category taxable amount (BT-116) =
  Σ(Invoice line net amounts for that category/rate)
  + Σ(Document level charge amounts for that category/rate)
  − Σ(Document level allowance amounts for that category/rate)

VAT category tax amount (BT-117) =
  BT-116 × (BT-119 ÷ 100)  [rounded to 2 decimals]
```

Note: Trailing zeros in VAT rate do NOT create separate breakdowns (15 and 15.00 = same breakdown).

### 8.2 Total VAT Calculation

```
BT-110 (Invoice total VAT) = Σ BT-117 (all VAT breakdown amounts)
```

Rounded at document level, NOT as sum of rounded line amounts.

## 11. Prepayment Invoice (Type Code 386)

- Invoice type code = `386` (prepayment invoice).
- When a final invoice adjusts a prepayment, the final invoice includes additional invoice lines with all amounts = 0 containing:
  - `cac:DocumentReference/cbc:ID` = prepayment invoice number (KSA-26)
  - `cac:DocumentReference/cbc:IssueDate` = prepayment issue date (KSA-28)
  - `cac:DocumentReference/cbc:IssueTime` = prepayment issue time (KSA-29)
  - `cac:DocumentReference/cbc:DocumentTypeCode` = `"386"` (KSA-30) — BR-KSA-74
  - `cac:TaxTotal` in the prepayment line with: KSA-31 (taxable), KSA-32 (tax), KSA-33 (category code), KSA-34 (rate)
- `cbc:PrepaidAmount` (BT-113) = Σ(KSA-31 + KSA-32) for all prepayment lines — BR-KSA-80.
- All numeric fields on prepayment adjustment lines must be 0: price, line extension, VAT amount, rounding amount — BR-KSA-82.
