# 01 — Brand Config Module + String Sweep

## Goal

Every brand-facing value (name, logo, domain, sender, links) comes from one typed config keyed by a `BRAND` env value. After this lands, the Merpec build contains zero occurrences of "Zerupt", enforced by CI.

## The module

New: `packages/shared/src/brand/` (exported from `@zerupt/shared`, same pattern as `pricing/`):

```
brand/
  types.ts      // BrandId = "zerupt" | "merpec"; Brand interface
  zerupt.ts     // the current values
  merpec.ts     // Merpec values (assets pending — see decisions.md open question 4)
  index.ts      // BRANDS record + resolveBrand(id) with fail-loud validation
```

`Brand` fields (add as needed, keep flat):

```ts
interface Brand {
  id: BrandId;
  name: string;                 // "Zerupt" | "Merpec"
  appUrl: string;               // https://app.zerupt.com | https://app.merpec.com
  apiUrl: string;
  logoMarkPath: string;         // /brand/<id>/logo-mark.png (assets namespaced per brand under public/brand/)
  pwaIcons: { i192: string; i512: string };
  themeColor: string;           // manifest theme/background
  emailFrom: string;            // "Zee at Zerupt <zee@mail.zerupt.com>" | "Merpec <no-reply@mail.merpec.com>"
  supportEmail: string;
  calLink: string | null;       // demo booking; null hides the CTA
  printAgentDownloadUrl: string | null;
  poweredByKey: string;         // i18n key, see below
  defaultLocale: "en" | "ar";   // merpec → "ar"
}
```

Resolution:
- **Web (build time):** `NEXT_PUBLIC_BRAND` env var → `resolveBrand()`. Unset/unknown value = build fails loudly (never default silently to zerupt; a wrong default is a brand leak).
- **API (request/tenant time):** the API serves both brands, so it resolves brand from the **tenant record** (`tenants.brand`, see 02), not from env. Brand-dependent API behavior today is only email sending (04) and the welcome-voice script.

Notes:
- i18n rule: brand name is a **runtime interpolation param**, never a translated literal — otherwise every locale file is a leak surface.
- Backend (`apps/api`) had no brand literals besides package names — keep it that way; `@zerupt/*` npm package names are internal and exempt from the sweep.

## Anti-leak CI gate (merge blocker)

Add to the web CI workflow:
1. `NEXT_PUBLIC_BRAND=merpec pnpm --filter @zerupt/web build`
2. Grep the build output (`.next/` static chunks + server output) and all `apps/web/messages/**/*.json` for case-insensitive `zerupt`, excluding sourcemap paths/package names (`@zerupt/`).
3. Any hit fails the build.

Cheap approximation until the full build-grep is wired: a Jest/Vitest test asserting no message file and no file under `src/` contains a user-visible `Zerupt` literal outside `brand/zerupt.ts`.
